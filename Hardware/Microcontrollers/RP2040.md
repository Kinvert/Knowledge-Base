# RP2040

`RP2040` is a low-cost microcontroller from Raspberry Pi, positioned as a high-value chip for embedded control, motor helpers, USB devices, and education. It is known for strong GPIO timing flexibility from the dual-core RISC-like system and [[PIO]] blocks.

---

## Overview

`RP2040` is part of Raspberry Pi’s microcontroller line and is the silicon behind boards like `Raspberry Pi Pico` and multiple third-party modules.

Key points:

- **Core:** dual-core ARM Cortex-M0+ (up to 133 MHz)
- **SRAM:** 264 KB
- **External flash only:** needs QSPI flash for program/storage (on-chip SRAM only)
- **GPIO:** 30 pins (depending on package/breakout)
- **Connectivity:** USB 1.1 controller, multiple digital interfaces
- **Programming model:** native C/C++ SDK + MicroPython ecosystem

---

## What makes RP2040 different

- `RP2040` gives you two Cortex-M0+ cores at a low price point, uncommon for this segment.
- `PIO` (Programmable I/O) lets you implement custom interfaces and timing-sensitive protocols in hardware-like state machines.
- SDK and toolchain are intentionally lightweight and easy for small projects.
- It has no integrated radio, so you add Wi-Fi/BLE via module over SPI/I2C/UART if needed.

---

## Core architecture

### CPU and memory

- 2× ARM Cortex-M0+ cores.
- 264 KB SRAM.
- Typically paired with off-chip QSPI flash (e.g., 2 MB on many dev boards).

Why this matters:

- Good for concurrency-heavy simple control (one core for timing, one for comms/state).
- No MMU and no hardware FPU, so it stays power-efficient and straightforward.

### Peripherals

- `PIO`: multiple state machines per controller for custom protocol timing.
- `PWM`: 16 channels.
- `ADC`: 12-bit SAR with multiple inputs + temp sensor input.
- `DMA`: multiple channels to move data without CPU cycles.
- Standard MCU mix: SPI/I2C/UART, timers, watchdog, comparators, RTC.

## Development workflow

### Common stacks

- Official stack: [[Raspberry Pi Pico SDK]] (`C`/`C++`) with `cmake`-driven build.
- Scripting: `MicroPython` support (good for rapid tests).
- Debugging: SWD with standard probes.

### Typical start sequence

1. Pick a board (for example `Raspberry Pi Pico`).
2. Set up `pico-sdk` and a toolchain.
3. Compile and flash via USB BOOTSEL flow or SWD.
4. For custom timing workloads, start with PIO examples instead of bit-banged GPIO.

---

## Power and performance profile

`RP2040` is not the lowest-power MCU for every case, but the performance-per-dollar is hard to beat for small systems.

- Good for medium-speed control loops.
- Capable of USB and multi-interface tasks simultaneously.
- Strong for mixed workloads: signal timing + comms + host command handling.

## Best use cases

- Tight custom timing IO (`PIO`) like LED driving, custom serial bridges, bus adapters.
- USB HID/CDC peripherals.
- Motor control and sensor-actuator bridges.
- Small robotics helpers, desk automation, CNC/3D printer tools where full Linux host isn’t needed.
- Teaching boards and quick hardware prototypes.

---

## Common gotchas

- You must budget external flash layout and XIP behavior.
- SRAM-only execution without flash mapping is not the default on common board flows.
- No hardware security enclave/secure boot unless you build your own trust architecture.
- For low-power long-sleep products, evaluate standby behavior carefully versus STM32 low-power lines.
